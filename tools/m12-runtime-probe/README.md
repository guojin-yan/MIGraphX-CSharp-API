# M12 package-only candidate probe

The runner resolves the repository, package feed, and evidence-record paths before restoring packages. A new record must be absent or empty and cannot overlap the repository or feed. The reviewer accepts only absolute, unique artifact-manifest entries inside the record and requires every critical review input to be covered by that manifest.

This project is a package-only `net10.0` probe for the M12 candidate package `0.0.0`. It has one exact core package reference and no `ProjectReference`, source assembly reference, native payload, provider installation step, or promotion path.

`run.sh` requires a clean detached source checkout, the exact core package hash, the fixed MIGraphX C header, the exact ONNX identity fixture, the generated TensorFlow GraphDef fixture, the generated calibration map, and an explicit native library path. It verifies the three model artifact hashes before restore and passes their absolute paths to the probe. The probe records the same fixture identities in both `identities.txt` and `m12-functional.json`; these checks bind the candidate record to reviewed bytes without claiming TensorFlow parser or quantization semantics. Package-source mapping permits `JYPPX.ROCm.MIGraphX.*` only from the supplied local feed; NuGet.org is permitted only for `Microsoft.*` and `NETStandard.Library` reference/build packages required to compile older target frameworks on the fixed .NET 10 SDK. Caches remain disabled and the isolated package closure is included in the artifact manifest. The runner records the native dependency closure and export set, then runs one 300-second bounded process with a 10-second TERM-to-KILL escalation. It does not inventory GPU devices, change the environment, or invoke long-running/timing scenarios.

The runner appends a JSONL case-stage trace before and after each functional case. `--case` accepts any of the fourteen in-process candidate case IDs for crash diagnosis, records that filter in metadata, and intentionally produces a partial record that `review.ps1` rejects as incomplete. A reviewable default run records `caseFilter: all`; a full candidate run can use `--include-deferred` to execute all fourteen functional paths plus the package-only cross-target ABI path and records `caseFilter: all-candidate`.

The default candidate run covers shape/argument factories, argument persistence and cloning, assign-to cloning, graph parent leases, graph editing, operation attributes, context lifetime, and the executable negative variadic/module ownership boundaries. The variadic boundary also checks deterministic typed scalar/array and Boolean-array attribute materialization without invoking a synthetic native operation. The deferred TensorFlow, quantization, custom-op registration, borrowed-device clone rejection, and concurrent-dispose paths are implemented and can be selected individually with `--case` or together with `--include-deferred` for one authorized diagnosis run. The borrowed-device case reflects only the package-internal external-buffer factory used by the optional adapter, then requires `Clone` to reject before copying and verifies that source bytes survive rejection and disposal; it does not allocate GPU memory and cannot promote the case. Full mode then runs the same exact package through `netcoreapp3.1`, `net7.0`, and `net10.0`, reflects the core assembly's compiled `DllImport`/`LibraryImport` strategy, and requires identical Identity output plus materialized reshape creation and cloning. These fifteen candidate paths still keep all eight semantic deferred IDs, and custom-op callback execution remains explicitly unverified, so no candidate is promoted by this record. The negative reflection and cross-target checks remain semantic-deferred until official runtime review. Every result is labelled `runtime-candidate-executed-review-required`.

When an official provider is available, `tools/m12-provider-callback-probe/provider-callback-probe.sh` can be run as a separate, explicitly authorized diagnostic. It exercises only managed callback reachability through a provider-owned graph path and writes an independent review record; it does not change this runner's fifteen-path candidate count, the M12 matrix, or any promotion decision. The probe exits non-zero when the callback is not observed, so a deferred result cannot be mistaken for successful provider execution.

`review.ps1` also recomputes the TensorFlow and calibration fixture hashes and checks that the result and identity manifest carry the same values. It only checks the candidate record's identity, exact executed/deferred case sets, timeout metadata, package hash, fixture identities, and artifact hashes. Its output is `candidate-record-verified`, not `runtime-executed`; it cannot alter `compatibility/m12-runtime-cases.json` or promote an M12 interface.
