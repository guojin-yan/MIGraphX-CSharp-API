# Provider callback invocation probe

`provider-callback-probe.sh` is an opt-in diagnostic for the M12 custom-op deferred boundary. It registers a managed custom op, creates an operation with the same name, inserts it into a program, and runs one of two explicit diagnostics: the default `--mode reachability` installs a shape callback that returns `UnknownError` after incrementing a managed counter; `--mode numerical-output` instead copies the input shape, declares host execution, and implements float32 elementwise `+1` in the compute callback. The numerical mode runs `[0.25, -1, 2, 9]` and requires `[1.25, 0, 3, 10]` exactly.

The probe is deliberately separate from `tools/m12-runtime-probe/run.sh`. It is not part of the default 14-functional-case candidate count and cannot promote `m12-custom-op-registration`. `review.ps1` requires a source/package-bound record, the mode-specific callback and graph outcome, and `promotionState: not-requested`; a missing callback is a diagnostic failure rather than a deferred success.

The numerical mode calls only official C API entry points to borrow the first input shape/argument and to access the host output buffer. Its callback sets `runs_on_offload_target` to false so the probe does not write through a device pointer. This diagnostic establishes one small host-side custom-op computation through the official provider, but does not claim the full custom-op lifecycle: output-alias behavior, arbitrary/dynamic shapes, concurrent execution, GPU callback memory, replay/copy/delete interaction, or exception/status containment during successful execution remain outside its evidence.

Neither diagnostic is part of the default 14-functional-case candidate count, and neither can promote `m12-custom-op-registration`. `review.ps1` verifies the mode-specific state, source/package identity, exact numeric vectors where applicable, artifact hashes, and `promotionState: not-requested`. A future promotion still requires the complete per-case criteria recorded in the M12 runtime matrix.

For local positive coverage, pass `--provider-fixture` to the probe with the repository's fake-native library. This enables the fixture-only dispatch hook so `migraphx_module_add_instruction` invokes the registered shape callback only for an operation with the same name and rejects that instruction with the controlled status. The focused graph-path tests additionally verify that a thrown managed exception is copied into a bounded 16-byte UTF-8 buffer before the status crosses back to native code, truncation never splits a multi-byte code point, and an unrelated operation neither invokes the callback nor changes its message buffer. The custom-op tests separately exercise native callback replacement, clearing, and current-state clone replay, native copy/delete callbacks, confirm their copied object points at the same managed state, and confirm delete still runs when the copied callback reports `UnknownError`. The hook is disabled by default, is not exported by the official MIGraphX provider, and its result remains test-substitute evidence.
