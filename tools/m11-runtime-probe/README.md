# M11 package-only runtime probe

This probe is source for a separately authorized official session. Its project has only exact package references to core/adapter `0.9.0-rc.9` and HipSharp `0.9.1`; it has no project reference or native payload.

`run-resilience.sh` requires a clean detached exact source SHA, transferred package hashes, fixed header, explicit MIGraphX/HIP paths, deterministic fixtures, a new evidence-record directory, and a local-only NuGet feed. It enforces the frozen 1,800-second session, a process-group-wide 10-second TERM-to-KILL escalation, and 120-second case boundaries, runs each repeated positive case three times, and uses a second process for the cache-restart hit. The `isolation`, `timing`, and `long-run` phases are separate package-only entry points: isolation loads two audited provider ELFs in fresh process order, timing stores all raw samples and recomputable statistics, and long-run stores one resource/output record per iteration. Long-run phases are split into independent 600-second probe processes; the aggregate JSON records every process report and the fixed restart interval. It never invokes GPU runtime inventory utilities; those belong to the separately bounded preflight. Candidate JSON is always `runtime-candidate-executed-review-required`.

`run-long-run-supervisor.sh` is that separate bounded long-run layer. It requires absolute executable paths for `rocm-smi` and `amd-smi`, captures a read-only `rocm-smi --showmeminfo vram --showuse` snapshot before and after exactly one phase, and keeps continuous `amd-smi` telemetry alive until the probe exits. It calls the probe with `--defer-artifact-manifest`, then writes the final manifest only after telemetry and the post-phase snapshot have both finished. A nonzero snapshot, telemetry, or probe exit fails the supervisor. The `host-async` phase additionally requires a sanitized JSON proof validated by `verify-restart-proof.py`; that validator checks a managed-to-host-async transition and differing pre/post boot fingerprints. The supervisor never performs or attests a host restart; the restart remains an independently authorized host operation.

The file/buffer case flushes structured start/completion markers to `raw/case-stages.jsonl` around parse, shape, compile, argument/map, run, readback, comparison, and resource teardown. A session-level KILL therefore preserves the last completed native boundary.

`review.ps1` is a separate reviewer. It recomputes package normalized identities, exact case sets, stage-trace completeness, result/artifact hashes, registry stability, source/assembly identity, timeout metadata, exit codes, and the sensitive scan before writing an external `runtime-executed` review result. It does not review or claim long-run/timing evidence.

`verify-supervisor-record.py` is a read-only post-run check. It validates phase metadata, zero exit codes, both snapshot files, non-empty telemetry with empty stderr, and every final manifest hash. It does not promote evidence; external review still decides whether phase-level results can be used for release.

Do not execute either script on an official host without a new Owner authorization naming the final source/package identities, host, time window, and test layer.
