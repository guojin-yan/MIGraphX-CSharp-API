# M12 local interface expansion

M12 is a local-development batch with a partially reviewed runtime record. It adds managed projections for the remaining generated C declarations without making a package-publication or performance claim. The core batch has passed local managed compilation, fake-native fixture compilation, focused M12 tests, representative interop execution, project-quality tests, and a package-only fake-native candidate run. The reviewed record establishes limited real MIGraphX runtime evidence for two case decisions; the later source-bound candidate exercised all thirteen implemented paths, while the remaining semantic cases stay deferred. The source/package-bound cloud records are kept in the outer `Radeon_Cloud/records/` directory; only `m12-context-lifetime` and `m12-operation-materialized-attributes` have independently reviewed promotion evidence, and no separate promotion was requested for the later candidate. The existing M3--M11 compatibility maps remain the evidence baseline.

## Implemented local surface

The managed API now contains the following resource-safe projections:

- `MIGraphXShape.CreateScalar`, `CreateWithStrides`, `Ndim`, `Index`, `GetDimensionLength`, `Clone`, and snapshot equality; `MIGraphXShapeCollection` and `MIGraphXDynamicDimensionCollection` preserve independent managed snapshots, including `GetDynamicDimensionCollection`.
- `MIGraphXArgument.CreateEmpty`, `Generate`, `Load`, `Save`, and `Clone`; host-backed argument and collection/map clone paths preserve independent ownership, while public clone explicitly rejects borrowed device arguments.
- Native assign-to clone paths for `MIGraphXTarget`, `MIGraphXCompileOptions`, `MIGraphXFileOptions`, `MIGraphXOnnxOptions`, and `MIGraphXProgram`.
- `MIGraphXProgram.Print`, `Sort`, `IsEqual`, `GetMainModule`, `CreateModule`, TensorFlow file/buffer parsing, quantization mutation methods, and experimental context acquisition.
- `MIGraphXModule`, `MIGraphXInstruction`, `MIGraphXInstructions`, `MIGraphXModules`, and the construction-restricted `MIGraphXOperation` managed graph handles. `MIGraphXOperation.Create` supports the proven no-attribute call shape plus typed, fully materialized common attributes; `MIGraphXOperationAttributes.ForReshape`, `ForTranspose`, `ForSlice`, `ForMultibroadcast`, and `ForTopK` materialize the five reviewed operation forms without C varargs. The generic builder covers signed/unsigned 32-bit and 64-bit integers, finite single/double values, Boolean, string, null, and matching arrays, including Boolean arrays. `Clone` creates an owned destination before native assign-to. Arbitrary C format placeholders and general varargs remain excluded. Module parameter/literal/return/allocation and instruction-with-module-args entry points retain the parent program lease.
- `MIGraphXTfOptions` with NHWC, input-shape, default-dimension, output-name, clone, and strict path/buffer parsing support.
- `MIGraphXQuantizeOpNames`, `MIGraphXQuantizeInt8Options`, and `MIGraphXQuantizeFp8Options`, including calibration-map forwarding and assign-to clones.
- `MIGraphXContext` with finish/queue access and program-lifetime leasing; context calls and lease release are serialized. `MIGraphXExperimentalCustomOp` keeps copy/delete and current user callback delegates rooted for the native registration lifetime, releases obsolete setter thunks after successful replacement or clear, explicitly keeps each setter thunk alive while its native setter consumes the function pointer, routes user callbacks through exception-contained native thunks, normalizes callback return values outside the frozen status enum to `UnknownError`, and clones by creating a new object and replaying the current callbacks.

All native `*_assign_to` declarations are treated as assignments into an already-created `T` handle, not as `T*` output-slot constructors. The managed clone helpers therefore create the destination first, invoke assign-to, and dispose that destination on failure. Collections additionally retain element/program leases so borrowed graph pointers cannot outlive their owners. Custom-op callback thunks are rooted per setter slot: a successful replacement or clear releases the obsolete thunk root, while a failed native setter preserves the previous thunk and managed callback. Explicit disposal and wrapper finalization share the same idempotent cleanup path, so callback captures are collectible after the native owner is destroyed even when the wrapper is abandoned. This keeps callback captures collectible during long-lived reconfiguration without allowing a native setter to observe an unrooted delegate.

The local fake-native source now models the added ownership classes, graph views, TensorFlow options, quantization mutations, context access, custom-op callback ownership, targeted failures, and null-output creation, including successful null borrowed argument buffers. Its test-only callback-invoke exports call each configured custom-op delegate with opaque arguments and exercise the exception-message buffer, while the opt-in provider dispatch fixture routes only a registered graph operation with the same name through the shape callback, supplies a bounded message buffer, and propagates its controlled status. Registration state in the fixture is committed only after a successful status, so a rejected registration cannot poison the provider registry and a later retry can be observed explicitly. `M12LocalInterfaceTests.cs` therefore verifies callback ABI entry, callback exception containment, undefined callback-status normalization, bounded UTF-8 message truncation at complete code-point boundaries, operation-name isolation, copy/delete state identity including cleanup after callback failure, replacement and clearing of the current callback with clone replay, obsolete callback-thunk root collection after replacement, the successful-setter thunk root through native-owner disposal, failed callback setter state preservation, failed registration rollback and retry, all four callback setter/dispose races, callback-root release after native owner disposal while the managed wrapper remains usable for fail-closed checks, non-empty literal buffer validation, quantize INT8 and TensorFlow output-name snapshot fail-closed behavior after disposal, clone callback rooting, registration, cleanup, and local graph-path reachability without claiming official provider registry behavior. The M10 registry path additionally rejects a native success that returns an empty operator name, so an unusable parser identifier cannot enter the copied capability snapshot. The fixture was compiled with the local MSVC toolchain, all twenty-five focused M12 tests pass on `net10.0`, and the graph path executes through both generated interop families on the representative `net46`, `netcoreapp3.1`, `net7.0`, and `net10.0` runners. The package probe additionally covers the five reviewed materialized operation-attribute factories and their clones.

Generated declarations remain source-of-truth and were not edited by hand. Internal raw-pointer aliases for shape metadata and collection-count EntryPoints allow caller-initialized output storage without changing the generated inventory. `NativeValueOutput` pre-fills enum, `size_t`, and pointer-plus-count slots with an `0xA5` sentinel outside the supported managed collection/allocation range, checks successful calls for unchanged slots, and only then copies the values. `NativeBorrowedOutput` rejects null borrowed handles immediately at their producing getter, so an invalid collection element cannot be passed into a later native call and misattributed there. The restricted one-input ONNX workflow also initializes its parameter-name pointer slot before `migraphx_program_parameter_shapes_names`, then rejects both a missing pointer and an empty decoded name, so native success without a usable identifier fails deterministically instead of reading uninitialized memory or reaching a later name lookup with an invalid key. The wrappers otherwise continue to use the existing `NativeResourceOwner`, `OutHandle`, strict UTF-8, size_t, and native-library identity boundaries.

## Local completion boundary

The ordinary `MIGraphXProgram.GetParameterShapes` snapshot now uses the same fail-closed native output contract as the restricted ONNX workflow: a successful empty parameter name or a duplicate name that cannot form a valid map is reported as `MIGraphXException` with the producing entry point, before any subsequent shape lookup. This keeps native string-output failures attributable to the getter that produced them.

Zero-parameter programs are also handled as a valid empty snapshot: after a second stable count read, the managed path returns without calling the native names writer with a null buffer. This preserves the native collection boundary for graphs that do not expose input parameters.

After indexed parameter-shape reads, the snapshot performs one final count check as well. A collection that changes after name enumeration or during shape materialization is rejected before the partially built managed map is exposed, matching the existing output-shape and run-output snapshot contract.

The restricted single-input ONNX workflow applies the same two-read stability check to parameter, compiled-output, and run-output collection counts before allocating or indexing native buffers. A count drift therefore fails at the producing collection instead of allowing a later names or element getter to observe an undersized managed buffer.

For the frozen declarations that have an ownership-safe public boundary, the local surface now has a managed projection, a value-semantic clone/equality alias, or an explicit immutable snapshot boundary. The one non-variadic declaration intentionally kept out of the public owner surface is `migraphx_module_create`: the frozen C header exposes no matching `migraphx_module_destroy`, and the manifest classifies its returned pointer as having no inferable public managed lifetime. Module views therefore enter through program-owned main/create-module paths. The compatibility maps still remain unchanged because this statement is an implementation inventory, not runtime evidence.

The operation boundary is also locked by a local reflection contract. `MIGraphXOperation` exposes exactly the no-attribute and fully materialized typed-attribute `Create` overloads; neither accepts `object`, pointer handles, or arbitrary `params` values. The attribute builder retains typed scalar and array forms, including deterministic Boolean-array materialization, but it does not expose an `object`/pointer carrier and the source gate rejects those ABI-shaped tokens. This proves managed signature closure only; it does not claim that arbitrary C variadic layouts are runtime-compatible.

The fake-native operation fixture additionally records the exact third argument received by the C entry point. The local operation tests assert that the no-attribute overload passes `NULL`, while the materialized path escapes a literal percent sign to `%%` before crossing the variadic declaration. Operation-name readback now pre-fills its fixed buffer with a non-string sentinel and performs bounded strict UTF-8 decoding; native success with an unwritten, unterminated, empty, or invalid name fails closed instead of returning an invented empty string or scanning past the allocation. The fixture injects the unwritten-output case through both `Name` and the name read performed by `Clone`. These checks close the managed-to-native text handoff and fixed-buffer readback regressions without claiming support for arbitrary format placeholders or other variadic values.

## Deliberately deferred

The following items still need a separate design or an authorized validation fixture before they can be promoted in the compatibility maps:

- `migraphx_operation_create` remains unsupported as a general C-varargs binding. `MIGraphXOperation.Create` exposes the proven no-attribute form and the typed materialized-attribute form; `Clone` uses a fresh owner followed by native `assign_to`. Arbitrary format placeholders and variadic values remain excluded.
- `migraphx_module_create` remains outside the public owner surface because the frozen declaration has no matching module-destroy operation; exposing it would require inventing an ownership contract.
- Native semantic coverage for loop iteration behavior, real external-data payloads, enabled exhaustive tuning, representative fast-math accuracy, quantization numerical results, TensorFlow model variants, custom-op callback execution, and context queue behavior is not established. The new TensorFlow and calibration artifacts are identity-checked fixtures only; they do not promote parser or quantization behavior. The package-only candidate now also exercises managed borrowed-buffer clone rejection and source-lease preservation through the adapter-internal state, but uses a guarded host allocation and does not claim real GPU device-memory evidence. A separate cross-target path exercises the exact core package under `netcoreapp3.1`, `net7.0`, and `net10.0`; both additions remain local/fake-native evidence until an authorized real-runtime record is reviewed.
- Low-level borrowed collection readback and dynamic-dimension native getter coverage remain represented by immutable managed snapshots rather than exposing dangling pointers.
- The M11 official functional, restart, long-run, timing, and Windows policy records are unchanged and remain validation-deferred.

The next validation batch should follow the [M12 real-runtime validation plan](../validation/m12-runtime-validation-plan.md), exercise the thirteen retained semantic cases against an authorized real MIGraphX installation, and review native ownership/callback behavior before any additional interface moves from planned/local-development to supported in a compatibility map.
