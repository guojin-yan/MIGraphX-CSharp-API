# M12 real-runtime validation plan

The core M12 local development batch is complete and its case-level evidence is partially reviewed; the current Boolean-array API follow-up remains local-only. The source/package-bound record promotes `m12-context-lifetime` and `m12-operation-materialized-attributes` only; the other thirteen cases remain `runtime-deferred`. Each authorized candidate is recorded in the outer `Radeon_Cloud/records/` directory. The standard cloud gate and package-only probe are independently reviewable, but no case is promoted automatically. This document, `compatibility/m12-runtime-cases.json`, and `compatibility/m12-post-build-runtime-evidence.json` define the execution and promotion boundary.

## Current status

The local Windows environment has no official MIGraphX provider. The fake MIGraphX and fake HIP fixtures, all 15 managed target frameworks, the ten M12 focused tests (including no-attribute and typed-materialized-attribute operation create/clone, explicit variadic/module ownership reflection boundaries, concurrent disposal races across module, argument, option, context, custom-op, and quantization owners), representative M12 graph execution through both interop families, the 46-test unit suite, the 27 ProjectQuality tests, the package tests, the four-TFM clean-consumer package audit, the managed-only net10.0 consumer execution, and the historical M11/API gates pass locally. That evidence proves managed ownership, package reachability, and ABI-shape contracts only; it does not prove behavior against MIGraphX 2.15.0.

The M12 matrix is intentionally separate from the historical M3-M11 maps. It records two `officialEvidence: runtime-executed` case decisions and thirteen `runtime-deferred` decisions; the matrix status is `partially-runtime-executed`. Its review policy requires the candidate label `runtime-candidate-executed-review-required` and the independent promotion record. No M12 case may be promoted directly by the runner or by a local test.

The source/package-bound candidate record is maintained outside the source tree under `Radeon_Cloud/records/`. The package-only probe runs nine bounded shape/argument/clone/graph/operation/context and negative-boundary cases by default and now contains four additional deferred candidate paths (TensorFlow parse, quantization, custom-op registration, and concurrent Dispose). They can be selected individually with `--case`, or all thirteen implemented paths can be executed in one bounded process with `--include-deferred` for the later single-session cloud run. The full mode still reports all eight semantic deferred IDs, and custom-op callback execution remains unverified. The negative reflection boundaries are executable package checks but remain semantic-deferred until official runtime review; cross-target paths remain static/deferred. The unified cloud gate performs the exact package/fixture preparation, full M12 candidate run, and independent review after the official M1 loader/object smoke and M2/M9 Identity candidate paths; the two promoted decisions remain source-bound and case-level.

## Required execution environment

An authorized run must bind all of the following before execution begins:

- Linux with the fixed MIGraphX 2.15.0 and ROCm 7.2.1 provider, plus the exact native header/library identity.
- A clean detached checkout of the final 40-character source SHA and exact managed package identities.
- A new record directory containing copied scripts, fixture/model hashes, package hashes, native dependency closure, process map, and UTC command metadata.
- A reviewed TensorFlow fixture and calibration map. The two ONNX identity fixtures inherit the frozen M11 SHA-256 values; local M12 fixtures are generated by `eng/generate-m12-fixtures.ps1` and hash-checked before an authorized run.
- A separately authorized observation policy for GPU/resource checks. The M12 runner must not modify the installed provider, reboot the host, or use an unreviewed alternate native root.

The fixed Windows policy remains unchanged: HIP SDK availability is not treated as MIGraphX availability, and no Windows native M12 session is designed.

## Execution layers

1. **Preflight and identity.** Verify source/package/native/fixture identities, native exports, target framework, OS/runtime versions, and a fresh evidence directory. Do not mark any case as runtime-executed.
2. **Bounded functional cases.** Run the shape/argument, assign-to, graph lease/edit, TensorFlow, quantization, context, custom-op, negative, concurrency, and representative ABI cases from the matrix. Record status codes, expected output/reference values, ownership counters where available, and the last completed synchronization/copy boundary.
3. **Independent review.** Recompute every artifact hash, verify the exact case set and candidate label, inspect sensitive fields, and compare result criteria with raw logs. Only this review may create a separate promotion record.
4. **Optional extended layers.** Long-run, timing, restart, or device-memory work requires a new authorization decision and separate evidence schema. It is not implied by passing the bounded M12 cases.

## Promotion boundary

Passing local tests does not change the historical `84/107/1` high-level map. The current managed API baseline is `45/309`; promotion is per case and requires the source/package-bound record plus independent review. The current record promotes only context lifetime and materialized operation attributes from its fixed source SHA; the later `SetBooleanArray` API addition remains local-only until a new candidate is independently reviewed. Typed, fully materialized operation attributes, including the five reviewed named factories, are supported without arbitrary C varargs; general format-placeholder calls and ownerless `migraphx_module_create` remain explicitly deferred unless a future header/ownership review changes their boundary.
