# M12 real-runtime validation plan

The core M12 local development batch is complete and its case-level evidence is partially reviewed; the later source-bound candidate also exercised the Boolean-array API follow-up without requesting a separate promotion. The source/package-bound record promotes `m12-context-lifetime` and `m12-operation-materialized-attributes` only; the remaining semantic cases stay `runtime-deferred`. Each authorized candidate is recorded in the outer `Radeon_Cloud/records/` directory. The standard cloud gate and package-only probe are independently reviewable, but no case is promoted automatically. This document, `compatibility/m12-runtime-cases.json`, and `compatibility/m12-post-build-runtime-evidence.json` define the execution and promotion boundary.

## Provider callback diagnostic

The opt-in `tools/m12-provider-callback-probe/` fixture is a separate diagnostic for the custom-op callback boundary. Its default reachability mode registers a managed custom op, inserts an operation with the same name into a provider graph, and returns `UnknownError` from the shape callback after incrementing a managed counter. Its separate `--mode numerical-output` mode copies the input shape, reports an empty alias list and host execution, and computes float32 elementwise `+1` on MIGraphX's host-side `ref` target. The latest authorized run on source SHA `59ee097de7f2eaef15d81ade24a40a6ac62a1af1` observed shape/compute/alias/offload callbacks with counts `2/1/2/2` and exact output `[1.25, 0, 3, 10]` for `[0.25, -1, 2, 9]`; its reviewed record is at `Radeon_Cloud/records/20260924-59ee097de-m12-custom-op-numeric/` and summarized by `compatibility/m12-provider-custom-op-numerical-diagnostic-59ee097.json`. This establishes one reference-target numerical callback execution for the latest package. It is not GPU/device-buffer evidence and does not cover non-empty aliasing, successful-compute exception conversion, native copy/delete balance, clone replay, repeated/concurrent calls, or promotion. For local positive coverage, `--provider-fixture` enables a fake-native-only dispatch hook at `migraphx_module_add_instruction`; that hook is disabled by default, checks that the operation name matches the registered custom op, and is not an official provider capability. The fake graph path also supplies a 16-byte callback message buffer, allowing the local test to verify bounded UTF-8 truncation when a managed exception is thrown; an unrelated operation succeeds without invoking the callback or mutating its message buffer. Both official modes keep `promotionState: not-requested`, remain separate from the standard fifteen-path candidate, and leave `m12-custom-op-registration` at `runtime-deferred`.

## Required execution environment

An authorized run must bind all of the following before execution begins:

- Linux with the fixed MIGraphX 2.15.0 and ROCm 7.2.1 provider, plus the exact native header/library identity.
- A clean detached checkout of the final 40-character source SHA and exact managed package identities.
- A new record directory containing copied scripts, fixture/model hashes, package hashes, native dependency closure, process map, and UTC command metadata.
- A reviewed TensorFlow fixture and calibration map. The two ONNX identity fixtures inherit the frozen M11 SHA-256 values; local M12 fixtures are generated by `eng/generate-m12-fixtures.ps1` and hash-checked before an authorized run.
- A separately authorized observation policy for GPU/resource checks. The M12 runner must not modify the installed provider, reboot the host, or use an unreviewed alternate native root.

The fixed Windows policy remains unchanged: HIP SDK availability is not treated as MIGraphX availability, and no Windows native M12 session is designed.

## Execution layers

1. **Preflight and identity.** Verify source/package/native/fixture identities, native exports, target framework, OS/runtime versions, and a fresh evidence directory. Do not mark any case as runtime-executed.
2. **Bounded functional cases.** Run the shape/argument, assign-to, graph lease/edit, TensorFlow, quantization, context, custom-op, negative, concurrency, and representative ABI cases from the matrix. Record status codes, expected output/reference values, ownership counters where available, and the last completed synchronization/copy boundary.
3. **Independent review.** Recompute every artifact hash, verify the exact case set and candidate label, inspect sensitive fields, and compare result criteria with raw logs. Only this review may create a separate promotion record.
4. **Optional extended layers.** Long-run, timing, restart, or device-memory work requires a new authorization decision and separate evidence schema. It is not implied by passing the bounded M12 cases.
