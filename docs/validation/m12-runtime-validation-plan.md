# M12 real-runtime validation plan

The core M12 local development batch is complete and its case-level evidence is partially reviewed; the later source-bound candidate also exercised the Boolean-array API follow-up without requesting a separate promotion. The source/package-bound record promotes `m12-context-lifetime` and `m12-operation-materialized-attributes` only; the remaining semantic cases stay `runtime-deferred`. Each authorized candidate is recorded in the outer `Radeon_Cloud/records/` directory. The standard cloud gate and package-only probe are independently reviewable, but no case is promoted automatically. This document, `compatibility/m12-runtime-cases.json`, and `compatibility/m12-post-build-runtime-evidence.json` define the execution and promotion boundary.

## Current status

The local Windows environment has no official MIGraphX provider. The fake MIGraphX and fake HIP fixtures, all 15 managed target frameworks, the twenty-five M12 focused tests (including no-attribute and typed-materialized-attribute operation create/clone, bounded operation-name readback and successful-but-unwritten output rejection through `Name` and `Clone`, non-empty literal null-buffer rejection before graph mutation, quantize INT8 and TensorFlow output-name snapshot fail-closed behavior after disposal, callback exception containment with code-point-safe UTF-8 truncation, undefined callback-status normalization to `UnknownError`, copy/delete state identity, callback replacement and clearing with current-state clone replay, obsolete callback-thunk root collection after replacement, successful-setter thunk rooting through native-owner disposal, failed callback setter state preservation, failed registration rollback and retry, all four callback setter/dispose races, callback-root release after native owner disposal while the managed wrapper remains usable for fail-closed checks, explicit variadic/module ownership reflection boundaries, the fake provider dispatch, exception, and operation-name isolation paths, and concurrent disposal races across module, argument, option, context, custom-op, and quantization owners), representative M12 graph execution through both interop families, the 62-test unit suite, the 27 ProjectQuality tests, the package tests, the four-TFM clean-consumer package audit, the managed-only net10.0 consumer execution, and the historical M11/API gates pass locally. M4/M5/M10 fault injection now also rejects successful-but-unwritten shape scalar/array metadata, collection counts, dynamic-dimension counts, and ONNX registry counts through caller-initialized raw output slots, plus successful null borrowed parameter/shape/run elements at their producing getters. That evidence proves managed ownership, package reachability, and ABI-shape contracts only; the provider dispatch result is a test substitute and does not prove behavior against MIGraphX 2.15.0 or official provider custom-op callback execution.

The M12 matrix is intentionally separate from the historical M3-M11 maps. It records two `officialEvidence: runtime-executed` case decisions and thirteen `runtime-deferred` decisions; the matrix status is `partially-runtime-executed`. Its review policy requires the candidate label `runtime-candidate-executed-review-required` and the independent promotion record. No M12 case may be promoted directly by the runner or by a local test.

The source/package-bound candidate record is maintained outside the source tree under `Radeon_Cloud/records/`. The package-only probe runs nine bounded shape/argument/clone/graph/operation/context and negative-boundary cases by default and contains four additional deferred functional paths (TensorFlow parse, quantization, custom-op registration, and concurrent Dispose). They can be selected individually with `--case`. Full `--include-deferred` mode executes all thirteen functional paths, then runs a fourteenth cross-target ABI path against the same exact package under `netcoreapp3.1`, `net7.0`, and `net10.0`; the reviewer requires the compiled core strategy to be `DllImport`, `LibraryImport`, and `LibraryImport` respectively, with equivalent Identity and materialized-operation results. The source mapping resolves the JYPPX package only from the exact local feed while allowing only Microsoft and NETStandard reference/build packages from NuGet.org for older-TFM compilation on the fixed .NET 10 SDK. Full mode still reports all eight semantic deferred IDs, and official custom-op callback execution remains unverified. The separate provider callback probe has a fake-native-only `--provider-fixture` mode for local reachability and controlled rejection; it is diagnostic-only, excluded from the fourteen-path candidate, and cannot promote the custom-op case. The negative reflection and cross-target boundaries remain semantic-deferred until official runtime review. The unified cloud gate performs the exact package/fixture preparation, full M12 candidate run, and independent review after the official M1 loader/object smoke and M2/M9 Identity candidate paths; the two promoted decisions remain source-bound and case-level.

The fake-native operation fixture now records the exact operation-create fixed arguments observed at the C boundary. Local coverage asserts that the no-attribute overload passes a null attributes pointer and that the materialized path escapes literal percent signs to `%%` before calling the variadic declaration. It also injects native success without writing the operation-name buffer; sentinel initialization and capacity-bounded strict UTF-8 decoding make both `Name` and `Clone` reject that output without reading beyond the allocation. These are ABI-boundary regressions only; they do not broaden support to arbitrary C varargs or format placeholders or promote real-provider name semantics.

The generic fake-native output injection also returns success without writing selected `size_t`, enum, or pointer-plus-count outputs. Internal raw aliases pass storage pre-filled with a `0xA5` pattern, so zero remains a legitimate empty collection or scalar-rank value while unchanged storage is rejected. Coverage includes shape type/lengths/strides/elements/bytes, parameter/output/run collection counts, dynamic-dimension count, and ONNX registry count. This remains local fault-containment evidence rather than a real-provider behavior claim.

## Provider callback diagnostic

The opt-in `tools/m12-provider-callback-probe/` fixture is a separate diagnostic for the custom-op callback boundary. It registers a managed custom op, inserts an operation with the same name into a provider graph, and returns `UnknownError` from the shape callback after incrementing a managed counter. For local positive coverage, `--provider-fixture` enables a fake-native-only dispatch hook at `migraphx_module_add_instruction`; that hook is disabled by default, checks that the operation name matches the registered custom op, and is not an official provider capability. The fake graph path also supplies a 16-byte callback message buffer, allowing the local test to verify bounded UTF-8 truncation when a managed exception is thrown; an unrelated operation succeeds without invoking the callback or mutating its message buffer. A verified record therefore proves callback reachability and controlled status propagation only. It does not prove numerical custom-op output, GPU execution, callback output ownership, or exception-buffer copy/delete behavior in a provider path. The runner fails closed when the callback is not observed, keeps `promotionState: not-requested`, and must not be folded into the standard fourteen-path candidate or used to promote `m12-custom-op-registration`. Promotion still requires a provider-owned operation fixture with independently reviewed output semantics.

## Required execution environment

An authorized run must bind all of the following before execution begins:

- Linux with the fixed MIGraphX 2.15.0 and ROCm 7.2.1 provider, plus the exact native header/library identity.
- A clean detached checkout of the final 40-character source SHA and exact managed package identities.
- A new record directory containing copied scripts, fixture/model hashes, package hashes, native dependency closure, process map, and UTC command metadata.
- A reviewed TensorFlow fixture and calibration map. The two ONNX identity fixtures inherit the frozen M11 SHA-256 values; local M12 fixtures are generated by `eng/generate-m12-fixtures.ps1` and hash-checked before an authorized run.
- A separately authorized observation policy for GPU/resource checks. The M12 runner must not modify the installed provider, reboot the host, or use an unreviewed alternate native root.

The fixed Windows policy remains unchanged: HIP SDK availability is not treated as MIGraphX availability, and no Windows native M12 session is designed.

## Execution layers

1. **Preflight and identity.** Verify source/package/native/fixture identities, native exports, target framework, OS/runtime versions, and a fresh evidence directory. Do not mark any case as runtime-executed.
2. **Bounded functional cases.** Run the shape/argument, assign-to, graph lease/edit, TensorFlow, quantization, context, custom-op, negative, concurrency, and representative ABI cases from the matrix. Record status codes, expected output/reference values, ownership counters where available, and the last completed synchronization/copy boundary.
3. **Independent review.** Recompute every artifact hash, verify the exact case set and candidate label, inspect sensitive fields, and compare result criteria with raw logs. Only this review may create a separate promotion record.
4. **Optional extended layers.** Long-run, timing, restart, or device-memory work requires a new authorization decision and separate evidence schema. It is not implied by passing the bounded M12 cases.

## Promotion boundary

Passing local tests does not change the historical `84/107/1` high-level map. The current managed API baseline is `45/309`; promotion is per case and requires the source/package-bound record plus independent review. The current records promote only context lifetime and materialized operation attributes from their fixed source SHA; the later `SetBooleanArray` API addition is covered by the `f0148bc` candidate but has no separate promotion request. Typed, fully materialized operation attributes, including the five reviewed named factories, are supported without arbitrary C varargs; general format-placeholder calls and ownerless `migraphx_module_create` remain explicitly deferred unless a future header/ownership review changes their boundary.
