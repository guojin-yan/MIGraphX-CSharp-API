# M8 authorized runtime, long-run, and performance methodology

This plan is executable only after the Owner authorizes one exact pushed commit, core/adapter/HipSharp hashes, host, and time window. Until then it is methodology, not runtime evidence.

## Fixed inputs and environment

The functional baseline is the repository-generated ONNX Identity float32 `[1,4]` model, SHA-256 `0b6fa0302a08a3fccf375d8ce4f84b7da59ccfa742fc59a0baa5f31722ae75f9`. It is generated by this project and has no third-party model license. Any additional representative model must be named with source, license, opset, input generator/seed, shape ranges, and SHA-256 before execution; otherwise performance comparison is omitted.

Use a clean detached checkout and exact local-feed managed packages. Record Ubuntu package identity, kernel, CPU/RAM, GPU/device/driver, clocks/power state, ROCm/MIGraphX APT versions, resolved native path, ELF/SONAME/export/`ldd`/process-map hashes, model/input hashes, command, UTC start/end, and exit code. Restart the host once after installation and repeat the environment probe.

## Functional and negative sequence

Run M1-M6 in order: loader/lifecycle/UTF-8; file and buffer parse/compile/synchronous reference; M4 typed/multi-output/exception/disposal; M5 static/dynamic overrides, Save/Load and cache miss/hit/corruption/concurrency/restart; M6 host async query/synchronize/early disposal/multiple streams/completion failure; M6 device input identity/lease/`offloadCopy=false`/explicit D2H/early disposal/error injection.

Run each isolation negative in a fresh process: missing MIGraphX, wrong architecture, missing dependency, missing export, explicit wrong path, second root, mixed private ROCm patch file, already-loaded different root, wrong device/stream/runtime client, disposed resource, tampered managed package, and incomplete/tampered cache. Preserve every failure sample and diagnostic classification.

## Timing boundaries

Measure parse, compile, cold cache, warm cache, synchronous run, host-async enqueue, host-async completion, device-input enqueue, device-input completion, H2D, D2H, and end-to-end separately. Every async sample ends at the correct stream completion boundary; enqueue time is never reported as execution time. Copy boundaries and compile options must match across comparisons.

For each eligible mode use 20 unreported warmups, then 200 measured iterations in each of 5 fresh processes. Randomize mode order per process from a recorded seed. Preserve raw samples and failures. Report count, failures, median, p95, minimum, maximum, and median absolute deviation; do not report only the best sample.

Record wall time, process CPU, peak/current RSS, GPU memory before/peak/after, disposal recovery, error count, device clocks/power, and system-noise notes. Performance comparison is allowed only for the same model/input, native family, target/options, synchronization, and copy boundary. Without an additional approved workload, publish functional timing samples only and make no faster/overlap/zero-copy claim.

## Long-run budget

After a 10-minute preflight, run three 60-minute phases: repeated parse/compile/run/dispose with cache restarts; host async across same and distinct streams with injected recoverable errors; device input with explicit D2H and early-dispose cases. Restart the process every 10 minutes and the host between the managed and async blocks. A final 30-minute mixed-order phase repeats cache corruption recovery and negative cases. Planned host reservation is 5 hours including installation audit and evidence packaging.

The run is successful only if all expected outputs match, expected negatives fail at their defined boundary, unexpected errors are zero, resource measurements return to the predeclared tolerance after disposal, and independent review verifies all identities and samples. Thresholds and iteration counts are frozen before the run and are not reduced after failures.
