# 0.0.0 engineering candidate

This unpublished local candidate includes M1 lifecycle work, M2's restricted ONNX workflow, M3's internal low-level binding pipeline, M4's resource-safe synchronous object layer, M5 dynamic shapes/Save/Load/cache, and the optional M6 HipSharp async adapter. The M6 mapping records 75 supported, 116 planned, and one unsupported high-level item over the fixed 192-item inventory. The single C-variadic function remains explicitly unsupported.

It includes no AMD native binary, fake binary, PDB, model binary, cache payload, or runtime package. M6 async execution lives only in the separate adapter candidate: fixed `hipStream_t`, explicit Query/Synchronize completion, early-dispose leases, validated `HipDeviceMemory` input, and explicit D2H output snapshots. Graph capture and arbitrary device pointers remain excluded. M4/M5/M6 evidence is local static and fake-native only. Official M1/M2 runtime validation passed at `f1a11cfd1701a041cee29188f7600c85b34ae260` for the recorded Ubuntu 24.04 / ROCm 7.2.1 / MIGraphX / gfx1100 environment and the generated static float32 Identity workflow; that older result does not validate M4, M5, or M6 objects and provides no zero-copy/performance claim.
