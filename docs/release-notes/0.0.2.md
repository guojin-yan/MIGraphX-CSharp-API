## 更新摘要

- 新增 `RunDeviceIntoAsync`，将模型结果写入调用方显存缓冲区，可继续执行 HIP 后处理。
- YOLO26 五任务与 PP-OCRv6 的数值前处理、后处理迁移至 GPU，保留 CPU 对照路径。
- OCR 新增多 batch、多识别实例，整图默认 batch=4、worker=2。
- 文本检测使用分块并行前缀扫描，减少整图文本框提取耗时。
- 补充完整流水线计时、案例说明与设备输出资源管理文档。

## 详细变更

### 核心 API 与 HIP 集成

`RunDeviceIntoAsync` 接受设备输入，以及与输出形状一一对应的调用方显存缓冲区。程序使用 `offloadCopy: false` 编译，模型输出通过同一 stream 上有序的 D2D 复制到达目标缓冲区，可继续提交 GPU 后处理，无需完整输出张量回传。

输入、输出、program 与原生结果在执行完成前保持有效，即使调用方提前 `Dispose` 也由在途任务保活；部分复制已提交后发生失败时也会等待并安全清理。此路径不创建主机张量快照，不能通过 `run.Outputs` 读取结果。原有同步与主机输出 API 保持原行为。

该接口使用 D2D 复制，不能视为零复制。缓冲区、形状、同设备与 stream 使用要求见 [HIP 集成指南](../guides/hip-interop.md)。

### YOLO26 GPU 流水线

覆盖 HIP 缩放、归一化、布局转换、分类 Top-5、检测框/旋转框/关键点解码，以及实例 mask 生成与计数。常规执行只回传紧凑结果，保存 mask 时再回传相应数据。使用方法见 [YOLO26 案例](https://github.com/guojin-yan/MIGraphX-CSharp-API/blob/v0.0.2/samples/Yolo26/README.md)。

### PP-OCRv6 GPU 流水线

覆盖检测预处理、8 邻域连通域、分块前缀扫描、凸包与最小面积矩形、框排序、透视裁剪、识别预处理和 CTC 解码。CPU 负责少量调度信息、最终 Unicode 映射与图片文件读写。

识别新增两个参数：

| 参数 | 范围 | 整图默认 | 仅识别默认 |
| --- | --- | --- | --- |
| `--rec-batch` | 1–32 | 4 | 1 |
| `--rec-workers` | 1–4 | 2 | 1 |

每个识别实例持有独立 MIGraphX program、非阻塞 HIP stream 和可写缓冲区。文本行按批提交，末批补零，只解码有效行，结果按原行号回填。模型需支持所选 batch；增大实例数与 batch 会增加编译与显存开销。使用方法见 [PP-OCRv6 案例](https://github.com/guojin-yan/MIGraphX-CSharp-API/blob/v0.0.2/samples/PaddleOcrV6/README.md)。

### 示例与文档

两个案例默认使用 `--backend hip`。通过 `--gpu-architecture` 指定 HIPRTC 编译架构，或用 `--hip-module` 指定预编译模块。`--backend cpu` 保留原来的 C# CPU 数值前后处理，且不接受识别 batch/worker 参数；两种后端均通过 MIGraphX 执行 GPU 模型推理。

HIP 分项使用 event 计时，模型阶段包含 D2D 输出复制；整图 pipeline 使用墙钟计时。多 stream 分项可能重叠，不能相加作为整图时间。详细计时定义见[视觉案例指南](../guides/vision-samples.md)。

## 兼容性与弃用项

- 破坏性变化：既有同步、主机输出 API 无需迁移；新增显存输出 API 按需使用。
- 弃用 API：本版本无新增弃用项。
- 案例默认行为：从 CPU 数值前后处理改为 HIP；保留旧行为时显式添加 `--backend cpu`。
- OCR 默认配置：整图 HIP 识别改为 batch=4、worker=2；需要顺序对照时使用 `--rec-batch 1 --rec-workers 1`。
- 依赖：核心包与适配包需同时使用 `0.0.2`；HipSharp 保持精确 `0.10.0`，原生基线不变。

## 升级方法

```bash
dotnet add package JYPPX.ROCm.MIGraphX.CSharp.API --version 0.0.2
# 使用 HIP 时同步升级适配包：
dotnet add package JYPPX.ROCm.MIGraphX.CSharp.API.HIP.Interop --version 0.0.2
```

1. 保持核心包与适配包版本一致；现有同步推理代码可以继续使用。
2. 运行新版案例时，提供与设备匹配的 `--gpu-architecture` 或预编译 `--hip-module`；保留旧前后处理时选择 CPU 后端。
3. 采用设备输出时，在编译后读取全部参数形状，为模型输入及编译器新增的输出/临时参数分配显存，再为每个模型输出准备独立目标缓冲区。
4. 后处理提交到同一 stream，或显式建立同步边界；完成后再复用/释放缓冲区。

包安装与离线源用法见[入门指南](../guides/getting-started.md)，完整设备使用模式见 [HIP 集成](../guides/hip-interop.md)。

## 性能参考

环境：Ubuntu 24.04、ROCm 7.2.1、MIGraphX 2.15.0、gfx1100、16 核 CPU 配额、FP32；每项预热 5 次、测量 30 次，GPU 频率与功耗未锁定。两列都使用 MIGraphX GPU 推理，比较的是 **CPU 数值前后处理**与 **HIP 数值前后处理**的整图墙钟时间。

| 模型 / 场景 | CPU 前后处理流水线，ms | HIP 流水线，ms | HIP P95，ms |
| --- | ---: | ---: | ---: |
| YOLO26 n 检测 | 15.77 | 2.75 | 2.83 |
| YOLO26 s 检测 | 18.57 | 4.46 | 4.56 |
| YOLO26 s 分类 | 5.46 | 1.50 | 1.53 |
| YOLO26 s 实例分割 | 61.30 | 7.44 | 7.55 |
| YOLO26 s 姿态 | 18.54 | 4.97 | 5.04 |
| YOLO26 s 旋转框 | 42.25 | 7.24 | 7.29 |
| PP-OCRv6 tiny / 16 行 | 66.09 | 10.97 | 11.08 |
| PP-OCRv6 small / 16 行 | 107.51 | 16.98 | 17.06 |
| PP-OCRv6 medium / 16 行 | 118.68 | 31.63 | 31.88 |

YOLO batch=1；OCR 检测 batch=1，CPU 对照按行识别，HIP 识别采用 batch=4、2 个独立实例。HIP 计时包含上传、GPU 前后处理、模型推理、D2D 输出复制与紧凑结果回传；CPU 路径包含 C# 前后处理和完整张量回读。两者均排除图片解码、模型/kernel 编译、绘图与文件导出。

同一最终 HIP 检测路径下，PP-OCRv6 tiny 16 行的识别调度对比如下：

| 识别配置 | 整图平均耗时，ms |
| --- | ---: |
| batch=1，worker=1 | 17.77 |
| batch=4，worker=1 | 11.50 |
| batch=4，worker=2 | 10.97 |

这些结果对应上述模型与设备，不能作为其他模型、图片或硬件的固定性能承诺。

## 已知限制

- GPU 预处理与 ImageSharp CPU 路径存在细小浮点/字节舍入差异，不承诺逐元素一致。
- 示例仍使用 ImageSharp 3.1.12，存在已知安全公告，当前面向可信本地图片；发布的核心包与适配包不依赖 ImageSharp。
- 上述 MIGraphX 2.15.0 环境中的姿态模型仍需 `MIGRAPHX_DISABLE_REDUCE_FUSION=1`。
- OCR 仍使用矩形 unclip，不包含页面方向分类、去畸变、表格或版面分析。
- 实验性自定义算子 GPU 回调、通用 C 可变参数和无销毁契约的独立 module 等边界见[平台说明](../compatibility/platforms.md)。

## 验证范围

两个正式包已完成 15 目标框架、API/包结构、独立消费及库依赖漏洞检查。实际发布构建在固定 GPU 基线上完成设备输出、同流后处理、提前释放、在途保护和缓冲区容量检查。

视觉案例覆盖六个 YOLO26 模型、三种 OCR 规格、仅识别、批处理尾批、单行与空白输入，并完成独立 ONNX Runtime CPU 张量及后处理对照。分块扫描覆盖顺序、偏移、部分块和容量边界。该验证范围不代表任意模型、设备或实验性运行语义均已支持。

## English Summary

- Core and adapter 0.0.2 add device output via ordered D2D copies and retain existing host-output APIs.
- YOLO26 and PP-OCRv6 now default to HIP numerical preprocessing/postprocessing; use `--backend cpu` for the original C# path.
- Full-image HIP OCR defaults to batch 4 with 2 recognition instances; recognition-only mode defaults to 1/1.
- Upgrade both MIGraphX packages together; the adapter still requires HipSharp 0.10.0. The native baseline remains Ubuntu 24.04, ROCm 7.2.1, MIGraphX 2.15.0 and gfx1100.
- The tables report whole-image pipeline latency, excluding decode, compilation, drawing and export. GPU clocks were not locked; results apply to the documented workloads.
