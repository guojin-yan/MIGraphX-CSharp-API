# 1.0.0 正式版本 / Stable release

发布日期：2026-11-17。接口包、HIP 适配包和平台 runtime 包使用稳定版本号 1.0.0；实际可获取状态以 NuGet 和 GitHub Release 为准。

Stable package line: 1.0.0. The core and optional HIP adapter retain their package names and matching versions. The HIP adapter now requires the published HipSharp 1.0.0 package (previously 0.10.0). The .NET Framework 4.6–4.8.1, .NET Core 3.1 and .NET 5–10 build matrix remains unchanged.

## 更新内容 / Changes

- 新增独立 Windows x64 与 Ubuntu 24.04 x64 runtime 包，包含 MIGraphX 2.18 引擎、设备代码、前端与 HIPRTC helper，以及文件哈希和许可证。ROCm 10.1 计算库、设备数据与显卡驱动仍需系统安装；详见[部署指南](../guides/runtime-deployment.md)。
- Windows 从选定引擎目录加载执行目标与序列化插件，无需额外添加 MIGraphX PATH；Linux 构建和发布输出补齐插件符号链接及 helper 执行权限。包消费回归包含独立进程保存、加载与参考推理。
- HIP 依赖从 0.10.0 升级到正式版 1.0.0，开发源码固定为 NuGet 包对应提交；构建、CI、独立消费者与发布证据统一校验该依赖。现有流提交和显存租约接口兼容，适配器公共 API 保持不变。

- 新增 ROCm 10.1 / MIGraphX 2.18 的 18 个可选 C API 绑定，以及功能组诊断、编译模式/目标 JSON、ONNX 维度参数、符号维度和执行跟踪元数据。缺失可选导出时明确拒绝调用，保留 2.15 基础接口。
- 补齐动态形状的保存、加载与缓存行为，包含缓存损坏重建、输入范围验证和克隆所有权回归。
- 四个视觉示例统一使用 OpenCV CSharp API 5.0.0 及对应平台 mini 原生包，移除旧图像依赖及其安全公告豁免。保留 RGB/BGR、OCR、mask、SVG、CLIP 和文档预处理功能。
- 纳入已在 main 开发的 OCR v4/v5/v6 统一选择、CLIP 与 PP-Structure 示例；模型与素材仍需独立准备。
- 增加 main/PR Windows 与 Ubuntu 自动构建、测试、包消费者及文档守卫；原生测试增加每组超时、进程树清理和独立日志。

Optional 2.18 functionality is detected from complete export groups. New image dependencies apply only to samples; the two published inference libraries stay independent of OpenCV. Trace results contain retained metadata, not intermediate GPU tensor copies or operator timings.

## 迁移 / Migration

应用升级时同时更新核心包与 HIP 适配包到 1.0.0，将显式 HipSharp 引用从 0.10.0 更新为 1.0.0。按部署平台添加对应 runtime 包，并安装 ROCm 10.1 系统依赖：

```bash
dotnet add package JYPPX.ROCm.MIGraphX.CSharp.API --version 1.0.0
dotnet add package JYPPX.ROCm.MIGraphX.CSharp.API.HIP.Interop --version 1.0.0
dotnet add package JYPPX.ROCm.HIP.CSharp.API --version 1.0.0
# Choose one platform runtime:
dotnet add package JYPPX.ROCm.MIGraphX.CSharp.API.Runtime.win-x64 --version 1.0.0
# dotnet add package JYPPX.ROCm.MIGraphX.CSharp.API.Runtime.ubuntu.24.04-x64 --version 1.0.0
```

示例需重新 restore 以获取 OpenCV 原生包；不要复用旧版本输出目录中的图像 DLL。见[图像迁移与平台包选择](../guides/opencv-imaging.md)和 [2.18 指南](../guides/runtime-2.18.md)。OpenCV 的 CPU 采样不承诺与旧图像库或 HIP 滤波逐元素相同，应重新验证业务数据。

## 验证范围与限制 / Scope and limitations

2.18 扩展已在本机 Windows 及 Ubuntu 24.04 / WSL2 的 ROCm 10.1 / MIGraphX 2.18 / gfx1100 环境验证。HipSharp 1.0.0、两个 MIGraphX 接口包与平台 runtime 组合通过独立构建、发布输出发现和真实 GPU 检查：Windows 25 项、Ubuntu 七组 30 项，包含显存输入输出、提前释放、多流隔离、HIPRTC 回调和资源循环；Ubuntu 另覆盖 FP16/BF16/INT8/FP8。旧 2.15 路径已有 Linux ROCm 7.2.1 / gfx1100 验证，该历史结果使用旧 HIP 依赖。具体原生依赖与兼容边界见[平台说明](../compatibility/platforms.md)。CI 在新运行时执行的旧 TFM smoke 不等于旧运行时资格认证。

- Linux 2.15 的部分默认 O3 编译存在 OCKL 链接问题，显式 O2 为该环境的已验证规避方法；托管层不自动降低优化等级。
- Windows 2.18 的 2×2 INT8 原生访问冲突尚存；32×32 回归通过不代表小矩阵问题已修复。
- Windows 本机原生构建没有 TensorFlow importer，托管层只能报告缺失功能。
- FormulaNet 在已验证的 MIGraphX 2.15 环境仍需显式选择 ORT CPU；未自动切换后端。
- OpenCV 迁移的图像回归不能替代完整模型数据集精度验证；历史性能数字不代表1.0.0 性能。

No claim is made for arbitrary models, devices or upstream native compiler fixes. Publishing requires a clean source commit, matching package provenance, independent consumers and the release workflow checks.
